# 交互流程

## 1. 首次进入

1. 打开应用 → hash 路由默认 `#/chat`
2. 读取 localStorage：
   - 无角色 → 聊天页显示空态："还没有角色，去创建一个" + 主按钮"新建角色" → 点击跳角色页
   - 有角色但无 API Key → 聊天页可正常浏览，点击发送时提示"请先配置 API Key" → 跳设置页
   - 有角色 + 有 Key + 该角色无会话 → 自动用开场白创建一条角色消息作为对话起点
3. 顶部显示当前角色名、使用的模型、连接状态点

## 2. 发送消息（核心流程）

1. 用户在文本域输入，按 Enter 发送（Shift+Enter 换行）；移动端点发送按钮
2. 追加用户消息气泡 → 清空输入 → 创建空的角色消息占位并显示"生成中"状态
3. 组装请求：
   - `messages = [{role:"system", content: 角色系统提示词}, ...最近 N 条历史消息, {role:"user", content: 本次输入}]`
   - `POST {baseURL}/chat/completions`，`Authorization: Bearer {apiKey}`，`stream: true`
4. 流式读取：解析 SSE `data:` 帧，取 `choices[0].delta.content` 逐字追加到占位消息
5. 生成中发送按钮变为"停止"：点击用 AbortController 中止请求，保留已生成内容
6. 结束：更新状态点、写入 localStorage、若出错则显示错误信息（可重试）
7. 自动滚动到底部（用户上滑查看历史时不强制滚动）

## 3. 角色管理

- **切换角色**：聊天页头部点角色名 → 角色抽屉滑出 → 点某角色 → 切换会话 → 抽屉关闭
- **新建角色**：角色页"新建"按钮 → 弹层填字段 → 保存 → 出现在列表并可选中
- **编辑角色**：角色卡片"编辑" → 同样弹层，预填现有值 → 保存覆盖
- **删除角色**：角色卡片"删除" → 确认弹层 → 删除角色及其会话 → 若删的是当前角色，自动切换到剩下的第一个（没有则回空态）
- **字段约束**：名称必填；系统提示词为空时使用默认值"你是一个角色扮演助手，请以角色身份回应。"；开场白可选

## 4. 设置

- 填写 Base URL（默认 `https://api.deepseek.com`）、API Key、模型（默认 `deepseek-chat`）
- 生成参数：温度 0–2（默认 1.2）、上下文消息数（默认 20）
- 保存 → 写入 localStorage → 顶部状态点变为"已连接"
- 数据管理：导出全部数据为 JSON 文件；清空所有数据（二次确认）

## 5. 异常处理

| 场景 | 表现 |
|---|---|
| 未填 API Key | 发送消息时内联提示 + 跳设置 |
| 401 / 余额不足 | 消息位置显示错误文本，状态点变红，提示检查 Key |
| 网络错误 / CORS | 显示"连接失败"，保留用户输入，可重试 |
| 流式中断 | 保留已收到内容，标注"已停止" |
| localStorage 写入失败 | 控制台警告 + 提示"本地存储已满" |

## 6. 待验证项
