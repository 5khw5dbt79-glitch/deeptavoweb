# 夜谈 · 角色对话

Tavo APP 对话体验的独立 Web 复刻：本地运行、多角色管理、接入 DeepSeek API、流式打字、APP 风格预设管理器（12 个提示词块）、可复用规则书、世界书与主角设定、token 用量调节。

## 本地运行

需要 Node.js（或任意静态文件服务器）：

```bash
cd tavo-web
npx serve .
# 或
python -m http.server 8080
```

浏览器打开 `http://localhost:3000`（serve 默认）或 `http://localhost:8080`（python）。

> 直接用 `file://` 打开 index.html 也可以，但部分浏览器对 ES Modules 有 CORS 限制，建议用本地 HTTP 服务。

## 使用步骤

1. 进入 **设置**，填写 DeepSeek API Key（`https://platform.deepseek.com` 申请），确认 API 地址为 `https://api.deepseek.com`、模型为 `deepseek-chat`（或 `deepseek-reasoner`），可先点「测试连接」确认可用，再保存
2. 进入 **角色**，新建角色，填写名称、系统提示词、开场白
3. （可选）进入 **规则书**，左侧「预设编排」选一套预设并点「启用」，右侧「规则片段库」开关想要的写作约束
4. （可选）点「预览 Context」核对真正会发出去的完整上下文（不发请求、不烧 token）
5. （可选）进入 **世界书**，填写主角（你自己）的身份、点选外貌标签（可自建词条、可传本地头像）、长期记忆，以及带关键词的世界设定
6. 回到 **对话**，输入消息，Enter 发送（Shift+Enter 换行），可看到逐字流式输出；输入框上方有「台词」「心理」「……」快捷键
7. 生成中点发送按钮可停止；回复下方的 ⟳ 可重新生成，`‹ 1 / N ›` 在多个版本间切换

## 规则书页：左编排器 + 右片段库

桌面是左右分栏：左边调注入顺序，右边管写作约束；窗口窄于 1080px 时自动变成两个 Tab（提示词编排 / 规则片段库）。

### 预设编排（左侧）

顶部下拉切换预设，右侧按钮启用 / 停用；「新建」「复制」「删除」在标题行。下方是当前预设的提示词块序列：

- 拖动手柄 `⋮⋮` 排序（也保留 ↑ ↓ 按钮，方便键盘与触屏）
- 点行内图标展开编辑内容，失焦即保存，不需要「保存」按钮
- 每行开关控制这一块本次是否注入
- 底部显示该预设的 `≈ token / 字符` 估算，以及「预览 Context」

内置四套：**沉浸叙事**（默认）、**细腻小说**、**快节奏对话**、**省流**。块的默认顺序按社区实践排列：

| 顺序 | 块 | 注入内容 |
| --- | --- | --- |
| 1 | Main Prompt | 主提示词，支持 `{{char}}` / `{{user}}` 宏 |
| 2 | World Info (Constant) | 常驻世界书条目 |
| 3 | Character Description | 角色的一句话简介 |
| 4 | Character Personality | 角色的系统提示词 |
| 5 | **Rule Snippets (Default)** | 注入位置为「角色设定后」的规则片段（槽位） |
| 6 | Persona | 主角（你自己）的档案 |
| 7 | Long-term Memory | 长期记忆 |
| 8 | World Info (Triggered) | 关键词触发的世界书条目 |
| 9 | Scenario / Enhance / Auxiliary | 你的自定义文本（默认关闭） |
| 10 | Chat Examples | `user: …` / `char: …` 多轮示例，作为独立消息 |
| 11 | Chat History | 历史对话（关闭后模型看不到之前的聊天） |
| 12 | Post-History Instructions | 历史之后、本次输入之前的额外指令 |
| 13 | **Rule Snippets (Depth 0)** | 注入位置为「历史底部」的规则片段（槽位） |

第 5、13 两个槽位不承载文本，只标记规则片段从哪一格流入，卡片上会显示「N 条规则流入」。拖拽右侧规则卡片到槽位上，就能把它的注入位置改成对应值。

### 预览 Context（Dry Run）

弹窗按真实发送顺序列出每条消息（system / user / assistant）、角色标签与 token 估算，并给出提示：底部规则插在第几条、是否有规则未生效、预算是否触发裁剪。预览与实际请求共用同一份组装代码，看到什么就发什么。

### 导入 / 导出

- **导入 SillyTavern 预设**：读取 `prompts` + `prompt_order`，映射 `main` / `worldInfoBefore` / `personaDescription` / `postHistoryInstructions` 等标识；对不上号的条目会作为自定义块保留，不丢内容
- **导出当前预设**：写成 SillyTavern 可读的 JSON（同时带 `extensions.yetan`，导出再导入无损）
- **导出配置**（页面右上角）：只导出预设 + 规则片段，不含 API Key 与聊天记录；改动累计 3 次后按钮上出现徽标，页面顶部也会提醒备份

## 规则片段

规则片段是**可复用的系统提示词片段**，每条都能单独设定「注入位置」和「生效范围」：

| 注入位置 | 落点 | 适合 |
| --- | --- | --- |
| 角色设定之后 | 系统提示词里，角色描述/性格之后（预设的 Rule Snippets 槽位） | 文风、排版、格式约束 |
| 主提示词顶部 | 系统提示词最前面 | 世界观基调、叙事边界 |
| 聊天历史底部 | 作为独立 system 消息插进历史末尾，`Depth 0` 紧贴最新一条 | 去 AI 腔、抗复读、字数刹车 |

- **生效范围**：全局，或仅指定角色（不选角色时按全局处理，避免规则静默失效）
- **拖拽**：把右侧卡片拖到左侧序列的槽位，注入位置随之改变并自动启用；卡片上的「+」按钮则一键放到默认位置
- 内置四条推荐片段（排版与克制文风 / 微距感官 / 言不由衷的推拉 / 字数刹车与互动留白），新装即启用；若一条都没启用，页面顶部会出现「载入推荐规则包」
- 未启用任何预设时，退回旧拼接：`全局前缀 → 主提示词 → 角色系统提示词 →（世界书 + 角色后规则，按预算裁剪）→ 全局后缀`，底部规则仍以独立消息插入
- **规则书按角色隔离**：页面顶部的「设定范围」决定你正在编辑谁的规则，切换角色时自动跟着切

> 说明：规则片段只是你自己的提示词文本，用来调整写作风格和输出格式。它无法改变 DeepSeek 服务端的内容安全策略——模型是否回答某个话题，由 API 服务商决定，客户端无法去除，本项目也不提供此类绕过手段。

## 世界书与主角

参考原 APP 的 `lorebook_v3` 结构与记忆接口，在 **世界书** 页可以管理三块内容：

| 模块 | 作用 | 生效方式 |
|---|---|---|
| 世界书条目 | 地点、组织、往事等设定 | 勾「常驻」则每次都带上；否则最近对话或本次输入出现任一触发关键词时自动加入 |
| 主角设定 | 你自己在故事中的身份、性格、外貌、背景、与角色的关系 | 打开开关后每次都带上；角色会按此称呼你，也会按外貌描述描写你的特征 |
| 长期记忆 | 已经发生、希望角色一直记住的事实 | 打开开关后每次都带上 |

- 关键词用逗号、中文逗号、竖线或换行分隔，不区分大小写
- 常驻条目优先于关键词触发条目；两者都排在角色设定之后
- 三条内置示例条目默认关闭，可随时开启、编辑或删除
- 所有内容只存浏览器本地，导出的备份里也包含世界书与主角数据

> 这些同样只是你自己的提示词文本，不会改变模型服务商的内容策略。

## 主角：本地头像与外貌标签

主角设定弹层里新增了两块，都是纯本地能力：

- **头像**：选择本地照片（iOS 相册、拍照都走 `accept="image/*"`）→ `<canvas>` 居中裁成正方形 → 等比缩放到 240×240 → `toDataURL('image/webp', 0.8)`；超过 25KB 时依次降低质量与尺寸。结果以 Base64 存进 localStorage，只用于聊天里的用户气泡和主角卡片，**不会进入任何 API 请求**
- **外貌标签**：三组预设词条（发型与发色 / 五官与气质 / 体型与穿搭）+ 你自己的自定义词条
  - 点一下标签就拼进下方「外貌补充与最终描述」，再点一次取消
  - 句末分隔用「，」，**已经手写的细节不会被覆盖**（先写「左腕戴着一只旧机械表」再点「眼角泪痣」，得到的是追加结果）
  - 自定义词条回车或点「添加」即生成胶囊，存在 `state.appearanceTags`（上限 40 条），点 × 删除；词条库跨角色共用，描述本身仍按角色隔离
- 外貌描述随 Persona 区块注入，形如 `玩家外貌：清冷疏离，白衬衫，左腕戴着一只旧机械表。`

## 角色图片（角色卡头像）

角色也能配图，走的是同一套本地压缩（`js/avatar.js`）：

- 角色编辑弹层顶部「上传角色图片」，选择后立刻压缩成 240×240 WebP（≤25KB），「移除图片」可恢复成色块首字
- 显示位置：角色卡片圆形头像、左侧角色列表的小圆图、对话里角色气泡的头像
- **聊天背景**：进入与该角色的对话时，这张图会作为聊天区背景（`cover` + 1.5px 模糊 + 暗色遮罩与四周收边），保证正文可读；没图或关掉开关就回到纯色。设置页可关闭「用角色图片作为聊天背景」
- 没配图时一律回落到原来的「标识色 + 名字首字」，老数据不需要迁移
- 图片只存在 localStorage，**不进入 API 请求**，也不影响任何提示词编排
- **格式与浏览器能力检测**：解码时先试 `createImageBitmap`、再回退 `<img>`；HEIC/HEIF 会先用 WebCodecs 的 `ImageDecoder.isTypeSupported()` 探测浏览器能力——能解就直接读，不能解才提示「请在相册里另存为 JPG / PNG」，而不是一律拦下

## iOS 与角色扮演交互

- **快捷输入**：输入框上方三枚按键「台词」「心理」「……」，插入 `「」`/`（）` 后光标停在中间；有选中文本时会把选区包起来
- **正文高亮**：`「台词」` 用暖琥珀，`（心理）` 用冷蓝。流式输出时未闭合的括号保持原样，闭合后才着色，不会出现半截高亮
- **Reroll 多版本**：每条 AI 回复下方 ⟳ 重新生成，旧版本保留在消息的 `variants` 里，用 `‹ 1 / N ›` 前后切换；切换后 `content` 同步更新，后续请求与预览读到的都是当前选中的版本
- **键盘适配**：监听 `window.visualViewport`，软键盘弹起时给 `--kb-inset` 赋值、收起底部导航栏，并把整页高度让给键盘；`viewport-fit=cover` + `env(safe-area-inset-*)` 处理刘海与底部横条
- **防缩放**：移动端输入控件字号统一 ≥16px，Safari 聚焦时不再自动放大

## 历史轮数与自动归档

- 「最大携带历史轮数」默认 **30 轮**（1 轮 = 你一句 + 角色一句），填 0 则回落到「消息条数」
- 历史条数超出窗口时，发送前会**静默**调用一次 `temperature: 0.2` 的请求，把最旧的 10 轮压成 200 字以内的结构化快照：

  ```
  - 当前时空 / 物理与衣着 / 关系与情绪张力 / 核心事件线 / 未解伏笔与约定
  ```

  快照写进该角色的长期记忆（与原记忆合并更新），这 10 轮原文从会话里剔除。归档失败不会阻塞发送，只是本次仍携带完整历史
- **发送前清洗**：界面保留完整排版，发给 API 的文本会折叠 3 个以上连续空行、去掉行尾空格与 `---` / `***` 这类纯装饰分隔线
- **缓存友好**：系统提示词、常驻世界书、角色卡、规则片段、主角外貌的顺序固定，且不插入任何时间戳或随机内容，DeepSeek 的上下文缓存更容易命中（输入按缓存命中价计费）

## 设定范围：每个角色一整套

规则书、世界书、主角、长期记忆都是**按角色整套隔离**的：不同角色可以有完全不同的世界观、不同的玩家身份、不同的剧情记忆，互不串台。

- 两个页面的顶部都有「设定范围」下拉，默认就是当前对话的角色；切换角色后会自动跟过去
- 第一次在某个角色名下做修改时，会自动把「通用设定」整套复制一份给该角色（下拉里标为 `· 独立`），此后它与通用彻底脱钩
- 想改动所有角色共用的模板，把范围切到「通用设定（模板）」；它同时是新建角色的初始值
- 新建角色时立即复制一份当前通用设定，所以改 A 的设定不会影响 B
- 某个角色想回到共用模板：点「恢复跟随通用」，丢弃它专属的那一套（有二次确认）

| 行为 | 结果 |
|---|---|
| 在「苏晚」里新建世界书条目 | 只有苏晚的对话会注入，霖不受影响 |
| 切到「霖」 | 世界书 / 规则书 / 主角 / 记忆一并切换成霖自己的那一套 |
| 在通用模板里改规则 | 只影响之后新建的角色，已独立的角色不受影响 |
| 删除角色 | 它的专属设定随之删除 |

> 老版本的数据全部落在「通用设定」里，升级后不需要迁移：没有独立设定的角色继续读取通用模板。

## 连通性测试

设置页的「测试连接」参考了 Tavo APP 的 API 设置：直接点按钮即可验证，**用当前表单里的地址和 Key 测试，不需要先保存**。

- 先发 `GET {地址}/v1/models` 拉取模型列表——**不消耗 token**，成功会列出可用模型（最多显示 12 个，点击即可填入上方的模型框）并显示响应耗时
- 若服务端未实现模型列表（404/405），自动回退到一次 `max_tokens: 1` 的最小聊天请求验证
- 分类反馈错误并给出排查建议：地址格式错误、把网址填进 Key、缺少 Key、密钥无效（401/403）、余额不足（402/429）、网络错误、超时
- 401/402 会直接判失败，不会浪费第二次请求
- **10 秒硬超时**：服务端挂住不响应时自动中止并提示「连接超时」，按钮不会一直卡在「测试中…」

> 这样你能先确认 Key 和地址是否正确，再决定要不要保存；聊天发不出去时也能快速判断是配置问题还是服务端问题。

## 用量与节省

Token 消耗主要来自**每次请求都重复发送的系统设定和历史消息**。设置页的「用量与节省」提供三个档位：

| 档位 | 历史轮数 | 历史字符 | 世界书条目 | 提示词预算 | 输出上限 |
|---|---|---|---|---|---|
| 省流 | 6 轮 | 1200 | 1 条 | 1200 | 1024 |
| 均衡（默认） | 30 轮 | 4000 | 3 条 | 4000 | 不限制 |
| 完整 | 0（按 100 条） | 不限制 | 不限制 | 不限制 | 不限制 |

- 点档位会立即保存并高亮；再手动改任一数字则取消高亮，按自定义值生效
- 页面下方会显示**当前配置实际会发送的设定字符/ token 数与历史字符/ token 数**。token 数是本地粗估（CJK 按 1、其他按 0.3），实际扣费以 API 返回的 usage 为准
- 提示词预算只裁剪「可裁剪块」（世界书 / 主角 / 角色描述 / 场景 / 规则书等），主提示词、角色性格与全局前后缀始终保留；裁剪以空行为单位，不会把一段设定从中间切断
- 启用对话预设时按你在编辑器里排定的块顺序逐块裁剪，**不会因为预算而打乱顺序**；剩余预算不够时靠后的可裁剪块整块省略
- 三个上限填 `0` 即不限制。省流档适合长对话或按量计费紧张时使用

> 顺带修复：此前历史数组按引用传递，本次输入会被重复放进历史消息里；现已改为发送前快照，同样的话不会额外计费。

## Token 用量检测

设置页的「Token 用量统计」显示**API 真实返回的 usage**，不是估算：

- 请求次数、输入 token、输出 token、合计 token 四项累计值，以及最近 7 天的按日明细
- 流式请求默认带上 `stream_options: { include_usage: true }`，DeepSeek 会在最后一帧返回 usage；非流式响应直接从 `usage` 字段读取
- 高级里可关闭「请求 API 返回 token 用量」，兼容不支持 `stream_options` 的中转服务（关闭后非流式用量仍可记录）
- 点「清零」只清除统计，不影响角色和对话
- 统计只存在本机浏览器，导出备份时会一并包含（API Key 仍默认脱敏）

注意：服务商返回的 `prompt_tokens` 是**整个请求**的输入量（含每次重复的设定与历史），不是单独某一句话。所以降低「用量与节省」里的上限，会直接体现在下一次请求的输入 token 上。

## 在 iPhone / iOS 上使用

iOS Safari 无法访问电脑上的 `localhost`。两种方案：

### 方案 A：局域网（最快，无需公网）

1. 让 iPhone 和电脑连**同一个 WiFi**
2. 查电脑局域网 IP：
   - macOS / Linux：`ipconfig getifaddr en0` 或 `hostname -I`
   - Windows：`ipconfig`，看「无线局域网适配器」的 IPv4 地址，一般是 `192.168.x.x`
3. 在电脑项目目录启动服务并监听所有网卡：
   ```bash
   python -m http.server 8080 --bind 0.0.0.0
   ```
4. iPhone Safari 打开 `http://电脑IP:8080`（例如 `http://192.168.1.23:8080`）
5. 点 Safari 底部分享按钮 → **添加到主屏幕**，之后像 App 一样全屏打开

> 注意：电脑必须保持开机、服务不能关；iPhone 锁屏或切换 WiFi 后地址会变。firewall 若拦截，需允许 8080 端口。

### 方案 B：公网链接（随时随地可用）

把项目发布成一个在线链接，iPhone 直接打开，同样可「添加到主屏幕」。这样不依赖电脑开机，但**任何拿到链接的人都能打开页面**（数据仍各存各的浏览器，API Key 只存本机，不会共享）。

### iOS 使用注意

- **数据存本地浏览器**：角色/对话/API Key 存在 Safari 的 localStorage。iOS 会在长期不访问后清理站点数据（ITP 机制），重要对话请定期用「设置 → 导出备份」保存 JSON
- **添加到主屏幕后是独立存储**：和 Safari 里打开的数据不互通，API Key 需要在新入口重新填一次
- **API Key 只存你的设备**：不会上传到任何服务器；DeepSeek 请求由你的手机浏览器直连（已验证可直连）
- **键盘遮挡**：已监听 `visualViewport`，键盘弹起时自动收起底部导航、把可视高度让给键盘，并把消息流滚到最新一条
- **添加到主屏幕**：`manifest.json` + `apple-touch-icon` 已就绪，`viewport-fit=cover` 配合 `env(safe-area-inset-*)` 处理刘海与底部横条
- **不会被自动放大**：移动端输入控件字号统一 ≥16px，Safari 聚焦输入框时不再缩放页面
