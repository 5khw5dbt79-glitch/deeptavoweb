# 夜谈 · 角色对话

Tavo APP 对话体验的独立 Web 复刻：本地运行、多角色管理、接入 DeepSeek API、流式打字、APP 风格预设管理器（12 个提示词块）、可复用规则书、世界书与主角设定、token 用量调节。

## 本地运行

需要 Node.js（或任意静态文件服务器）：

```bash
cd tavo-web
npx serve .
# 或
python -m http.server 8080
```

浏览器打开 `http://localhost:3000`（serve 默认）或 `http://localhost:8080`（python）。

> 直接用 `file://` 打开 index.html 也可以，但部分浏览器对 ES Modules 有 CORS 限制，建议用本地 HTTP 服务。

## 使用步骤

1. 进入 **设置**，填写 DeepSeek API Key（`https://platform.deepseek.com` 申请），确认 API 地址为 `https://api.deepseek.com`、模型为 `deepseek-chat`（或 `deepseek-reasoner`），保存
2. 进入 **角色**，新建角色，填写名称、系统提示词、开场白
3. （可选）进入 **规则书** 页顶部，启用一份预设（内置「默认」或「轻缩」，也可新建），一次一个
4. （可选）点预设卡片右侧的「⋯」可编辑、设为默认或删除；编辑器里能开关、排序、改写 12 个提示词块
5. （可选）进入 **世界书**，填写主角（你自己）的身份、长期记忆，以及带关键词的世界设定
6. 回到 **对话**，输入消息，Enter 发送（Shift+Enter 换行），可看到逐字流式输出
7. 生成中点发送按钮可停止

## 预设（对应 APP 的「预设」页）

规则书页顶部是完整复刻的预设管理器：搜索、新建、启用/停用、设为默认、编辑、删除。内置两份：

- **默认**：完整注入角色、世界书、主角、对话示例等 9 个块，主提示词取自 APK 官方深度扮演提示词
- **轻缩**：只开启主提示词、角色性格、对话历史 3 个块，显著减少 token（与 APP 的「轻缩」思路一致）

点「新建」进入整页编辑器，包含 APP 中的 12 个提示词块：

`Main Prompt` / `Lorebook Before` / `Persona Description` / `Char Description` / `Char Personality` / `Scenario` / `Enhance Definitions` / `Auxiliary Prompt` / `Lorebook After` / `Chat Examples` / `Chat History` / `Post-History Instructions`

每块都可以开关（关闭后移到「未激活提示词」）、用 ↑↓ 调整顺序、编辑内容；还可以「添加」自定义块。块的含义：

| 块 | 注入内容 |
| --- | --- |
| Main Prompt | 预设的「基础提示词」，支持 `{{char}}` / `{{user}}` 宏 |
| Lorebook Before | 长期记忆 + 常驻世界书条目 |
| Persona Description | 主角（你自己）的档案 |
| Char Description / Char Personality | 角色的一句话简介 / 系统提示词 |
| Scenario / Enhance Definitions / Auxiliary Prompt | 你的自定义文本 |
| Lorebook After | 关键词触发的世界书条目 |
| Chat Examples | `用户：…` / `角色：…` 格式的多轮示例，作为独立消息注入 |
| Chat History | 历史对话消息（关闭后模型看不到之前的聊天） |
| Post-History Instructions | 历史之后、本次输入之前追加的指令 |

启用预设后，发给模型的消息严格按上面块的顺序组装；未启用任何预设时退回原有的拼接方式。预设与块的开关、顺序都会保存在浏览器本地。

## 规则书

规则书是**可复用的系统提示词片段**，与角色设定叠加。未启用预设时的拼接顺序为：

```
全局前缀 → 对话预设主提示词 → 角色系统提示词 → 世界书 → 已启用的规则书 → 全局后缀
```

- 内置两条中性规则（叙事口吻 / 对白驱动），默认关闭，按需开启
- 可新建任意条自定义规则，随时开关、编辑、删除
- 前缀/后缀在 **设置 → 高级** 里填写

> 说明：规则书只是你自己的提示词文本，用来调整写作风格和输出格式。它无法改变 DeepSeek 服务端的内容安全策略——模型是否回答某个话题，由 API 服务商决定，客户端无法去除，本项目也不提供此类绕过手段。

## 世界书与主角

参考原 APP 的 `lorebook_v3` 结构与记忆接口，在 **世界书** 页可以管理三块内容：

| 模块 | 作用 | 生效方式 |
|---|---|---|
| 世界书条目 | 地点、组织、往事等设定 | 勾「常驻」则每次都带上；否则最近对话或本次输入出现任一触发关键词时自动加入 |
| 主角设定 | 你自己在故事中的身份、性格、背景、与角色的关系 | 打开开关后每次都带上；角色会按此称呼你，且不会替你决定言行 |
| 长期记忆 | 已经发生、希望角色一直记住的事实 | 打开开关后每次都带上 |

- 关键词用逗号、中文逗号、竖线或换行分隔，不区分大小写
- 常驻条目优先于关键词触发条目；两者都排在角色设定之后
- 三条内置示例条目默认关闭，可随时开启、编辑或删除
- 所有内容只存浏览器本地，导出的备份里也包含世界书与主角数据

> 这些同样只是你自己的提示词文本，不会改变模型服务商的内容策略。

## 可调参数（设置页）

| 参数 | 范围 | 说明 |
|---|---|---|
| Temperature | 0–5 | 越高越发散；DeepSeek 建议 0–2 |
| Top P | 0–1 | 核采样，一般保持 1 |
| 单次回复上限 | 0–32000 token | 0 = 不限制 |
| 携带历史消息数 | 1–500 条 | 实际可用量受模型上下文窗口与余额限制 |
| 流式输出 | 开/关 | 关闭后等完整回复 |
| 请求用量统计 | 开/关 | 对应 `stream_options.include_usage`，关闭后不再请求 API 返回用量 |
| 全局前后缀 | 任意文本 | 追加到 system 提示词 |
| 历史消息字符上限 | 0–200000 字符 | 超限时从最早消息开始丢弃，至少保留最近一条 |
| 世界书条目上限 | 0–50 条 | 一次最多注入几条世界书条目，常驻优先 |
| 提示词字符预算 | 0–100000 字符 | 限制世界书 + 规则书合计长度，按空行分段裁剪 |
| 用量预设 | 省流/均衡/完整 | 一键设置上面几项与输出上限 |

## 用量与节省

Token 消耗主要来自**每次请求都重复发送的系统设定和历史消息**。设置页的「用量与节省」提供三个档位：

| 档位 | 历史消息 | 历史字符 | 世界书条目 | 提示词预算 | 输出上限 |
|---|---|---|---|---|---|
| 省流 | 8 条 | 1200 | 1 条 | 1200 | 1024 |
| 均衡（默认） | 20 条 | 4000 | 3 条 | 4000 | 不限制 |
| 完整 | 100 条 | 不限制 | 不限制 | 不限制 | 不限制 |

- 点档位会立即保存并高亮；再手动改任一数字则取消高亮，按自定义值生效
- 页面下方会显示**当前配置实际会发送的设定字符/ token 数与历史字符/ token 数**。token 数是本地粗估（CJK 按 1、其他按 0.3），实际扣费以 API 返回的 usage 为准
- 提示词预算只裁剪「世界书 + 规则书」，角色设定和全局前后缀始终保留；裁剪以空行为单位，不会把一段设定从中间切断
- 三个上限填 `0` 即不限制。省流档适合长对话或按量计费紧张时使用

> 顺带修复：此前历史数组按引用传递，本次输入会被重复放进历史消息里；现已改为发送前快照，同样的话不会额外计费。

## Token 用量检测

设置页的「Token 用量统计」显示**API 真实返回的 usage**，不是估算：

- 请求次数、输入 token、输出 token、合计 token 四项累计值，以及最近 7 天的按日明细
- 流式请求默认带上 `stream_options: { include_usage: true }`，DeepSeek 会在最后一帧返回 usage；非流式响应直接从 `usage` 字段读取
- 高级里可关闭「请求 API 返回 token 用量」，兼容不支持 `stream_options` 的中转服务（关闭后非流式用量仍可记录）
- 点「清零」只清除统计，不影响角色和对话
- 统计只存在本机浏览器，导出备份时会一并包含（API Key 仍默认脱敏）

注意：服务商返回的 `prompt_tokens` 是**整个请求**的输入量（含每次重复的设定与历史），不是单独某一句话。所以降低「用量与节省」里的上限，会直接体现在下一次请求的输入 token 上。

## 在 iPhone / iOS 上使用

iOS Safari 无法访问电脑上的 `localhost`。两种方案：

### 方案 A：局域网（最快，无需公网）

1. 让 iPhone 和电脑连**同一个 WiFi**
2. 查电脑局域网 IP：
   - macOS / Linux：`ipconfig getifaddr en0` 或 `hostname -I`
   - Windows：`ipconfig`，看「无线局域网适配器」的 IPv4 地址，一般是 `192.168.x.x`
3. 在电脑项目目录启动服务并监听所有网卡：
   ```bash
   python -m http.server 8080 --bind 0.0.0.0
   ```
4. iPhone Safari 打开 `http://电脑IP:8080`（例如 `http://192.168.1.23:8080`）
5. 点 Safari 底部分享按钮 → **添加到主屏幕**，之后像 App 一样全屏打开

> 注意：电脑必须保持开机、服务不能关；iPhone 锁屏或切换 WiFi 后地址会变。firewall 若拦截，需允许 8080 端口。

### 方案 B：公网链接（随时随地可用）

把项目发布成一个在线链接，iPhone 直接打开，同样可「添加到主屏幕」。这样不依赖电脑开机，但**任何拿到链接的人都能打开页面**（数据仍各存各的浏览器，API Key 只存本机，不会共享）。

### iOS 使用注意

- **数据存本地浏览器**：角色/对话/API Key 存在 Safari 的 localStorage。iOS 会在长期不访问后清理站点数据（ITP 机制），重要对话请定期用「设置 → 导出备份」保存 JSON
- **添加到主屏幕后是独立存储**：和 Safari 里打开的数据不互通，API Key 需要在新入口重新填一次
- **API Key 只存你的设备**：不会上传到任何服务器；DeepSeek 请求由你的手机浏览器直连（已验证可直连）
- **键盘遮挡**：输入框在底部导航上方，iOS Safari 弹起键盘时页面会自动滚动到输入框

## 数据

- 所有角色、规则、预设、世界书、主角、记忆、对话、设置保存在浏览器 localStorage（键 `tavo-web:v1`），刷新不丢
- 设置页可导出 JSON 备份（默认脱敏 API Key）或清空数据
- API Key 仅存本机，不经过任何中继服务器
